The mechanism

How Porter works

No dashboards to babysit, no YAML to write. Your device talks to the Connector Portal, the portal brokers your Cloudflare identity, and Porter does the rest.

1

Install & run

One dynamic installer detects your platform — Linux, macOS, Termux or WSL — installs Python, cloudflared, dependencies and the porter CLI. A systemd/launchd service keeps it alive.

2

Link the Connector Portal

Sign in with your portal account (porter cf portal-login). The password is exchanged once for a scoped device API key and is never stored on the device.

3

Pick accounts · verified instantly

The portal lists every connected Cloudflare account. Choose one or many. Each pulled set is proven with a forced token refresh — you see VERIFIED ✓ or FAILED ✗ immediately.

4

Tunnel & self-heal

Create tunnels per subdomain straight from the dashboard. Expired tokens refresh automatically; if rotation broke them, Porter re-pulls from the portal before failing.

Why Porter

Built for headless reality

Raspberry Pis, VPS boxes, Termux phones, CI containers — anywhere a browser isn't guaranteed.

⧉

Multi-account

Store several Cloudflare accounts locally, switch active with one command, forget devices cleanly.

✓

Verified connections

Every linked account gets exactly one forced OAuth refresh — success or failure surfaces instantly, never silently.

↻

Self-healing tokens

Refresh → re-pull fallback chain keeps tunnels breathing when tokens rotate elsewhere.

⛨

Password never stored

Portal passwords exchange once for a device API key. Tokens sit AES-256-GCM encrypted on the portal.

⌘

Full CLI parity

Everything the web UI does lives under porter cf … — scriptable, SSH-friendly.

◈

One installer

Detects distro, package manager, CPU arch and service manager. Same file everywhere.

Headless CLI

porter cf — the connector toolkit

porter cf portal-login [url]link device · blank URL = primary portal
porter cf connectionslist portal accounts (+stored)
porter cf use <id>switch active · offline fallback
porter cf syncre-pull + verify active account
porter cf accountslocal accounts w/ verify badges
porter cf forget <prefix>remove an account from device
porter server start|stop|statuscontrol the local portal server
porter tunnel create|list|deletetunnel lifecycle from terminal
