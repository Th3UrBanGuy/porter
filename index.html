The Mechanism

How Porter works

No dashboards to babysit, no YAML to write. Your device talks to the Connector Portal, the portal brokers your Cloudflare identity, and Porter does the rest.

1

Install & run

One dynamic installer detects your platform — Linux, macOS, Termux or WSL — installs Python, cloudflared, dependencies and the porter CLI. A systemd/launchd service keeps it alive.

2

Link the Connector Portal

Sign in with your portal account (porter login). The password is exchanged once for a scoped device API key and is never stored on the device.

3

Pick accounts · verified instantly

The portal lists every connected Cloudflare account. Choose one or many. Each pulled set is proven with a forced token refresh — you see VERIFIED or FAILED immediately.

4

Tunnel & self-heal

Create tunnels per subdomain straight from the dashboard. Expired tokens refresh automatically; if rotation broke them, Porter re-pulls from the portal before failing.

Headless CLI

porter — the connector toolkit

Every feature accessible from the terminal. Scriptable, SSH-friendly, automatable.

porter loginlink device to portal
porter cf portal-login [url]link device · blank URL = primary
porter cf connectionslist portal accounts (+stored)
porter cf use <id>switch active · offline fallback
porter cf syncre-pull + verify active account
porter cf portal-statusportal connection status
porter cf accountslocal accounts w/ verify badges
porter cf forget <prefix>remove an account from device
porter tunnel create <sub> <port>expose a local service
porter tunnelslist all active tunnels
porter server start|stop|statuscontrol the local server
porter shorturl <url>shorten a tunnel URL
